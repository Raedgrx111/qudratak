# قدراتك | Qudratak 🎓

منصة سعودية متكاملة للتدريب على **اختبار القدرات العامة (قياس / GAT)** — تطبيق ويب كامل (Full-Stack) مبني بـ Next.js 16 و TypeScript مع واجهة عربية RTL كاملة.

> **حالة المشروع:** جاهز للإنتاج — بنك يضم **1,300+ سؤال** حقيقي الطابع، اختبارات محاكاة بمؤقت، تصحيح آلي، تحليل أداء، نقاشات تعليمية، مساعد ذكي، ولوحة معلم شاملة.

---

## ✨ المزايا

### 🧑‍🎓 نظام الطلاب
- إنشاء حساب / تسجيل دخول / خروج آمن (JWT + bcrypt مخزّن في HttpOnly Cookie مع بديل Bearer Token)
- ملف شخصي قابل للتحديث (الاسم، المرحلة الدراسية)
- تتبع كل سؤال تم حله (تدريب أو اختبار) بدقة على مستوى الموضوع
- كشف تلقائي **لنقاط الضعف** (دقة < 65%) و**نقاط القوة** (دقة ≥ 75%)
- توصيات تدريب مخصصة مع زر «ابدأ تدريبًا مكثفًا» يولّد اختبارًا فوريًا
- حفظ الأسئلة المفضلة للمراجعة
- منحنى تقدم 14 يومًا (Recharts)

### 📚 نظام الأسئلة
- كل سؤال: قسم (كمي/لفظي) + موضوع تفصيلي (16 موضوعًا) + صعوبة (سهل/متوسط/صعب) + نص + 4 خيارات + إجابة صحيحة + شرح مفصل + **صورة SVG هندسية** عند الحاجة
- بحث نصي + فلترة بالقسم/الموضوع/الصعوبة + صفحات
- **استيراد ملفات Excel / CSV** بآلاف الأسئلة مع تحقق من كل صف وتقرير أخطاء مفصل
- تنزيل قالب استيراد جاهز (xlsx)
- إضافة/تعديل/حذف الأسئلة (معلم)

### ⏱️ نظام الاختبارات
- 6 اختبارات جاهزة: محاكاة شاملة (كمي+لفظي)، قسم كامل، تدريب مهارة مركّز
- مؤقت تنازلي حقيقي مع **تسليم تلقائي عند انتهاء الوقت**
- لوحة تنقل بين الأسئلة + شريط تقدم
- تصحيح آلي فوري + تحليل: الدقة حسب الموضوع والقسم، الزمن، خطة ما بعد الاختبار
- إنشاء اختبارات جديدة بتوليد تلقائي (عدد/قسم/موضوع/مدة)

### 💬 النقاشات
- تعليقات أسفل كل سؤال مع **ردود متداخلة**
- إعجابات (واحدة لكل مستخدم لكل تعليق)
- المعلم: **تثبيت** التعليقات المهمة و**حذف** غير المناسب
- إشراف مركزي بأحدث التعليقات

### 📺 المقاطع التعليمية
- مكتبة دروس مرئية يديرها المالك/المعلم: يلصق **رابط يوتيوب** (watch / youtu.be / shorts) أو **رابط ملف mp4 مباشر** فيُكتشف النوع تلقائيًا
- **رفع من الجهاز**: زر «رفع من جهازي» في لوحة الإدارة — سحب وإفلات أو اختيار فيديو (mp4/webm/mov/m4v/mkv/ogv) حتى **500MB** مع شريط تقدم حقيقي بالنسبة المئوية
- بعد الرفع تلقائيًا: توليد **صورة مصغرة** من إطار الفيديو (ffmpeg) + استخراج **المدة** (ffprobe) — وتظهر في البطاقات والمشغل
- صفحة `/clips` للطلاب: شبكة بطاقات بصور مصغرة من يوتيوب أو الملفات المرفوعة، فلترة (كمي / لفظي / عام) + موضوع تفصيلي
- صفحة مشاهدة مخصصة `/clips/:id` لكل مقطع (قابلة للمشاركة) مع **زر نسخ الرابط** على البطاقات والصفحة، ومقاطع ذات صلة من نفس القسم
- عدّاد مشاهدات حقيقي + شريط «أحدث المقاطع» في لوحة الطالب (كل بطاقة تفتح صفحة المقطع مباشرة)
- إدارة كاملة من لوحة المالك/المعلم (تبويب المقاطع): إضافة، **رفع**، تعديل، نشر/إخفاء، حذف (يحذف ملفات القرص أيضًا) — مع معاينة مصغرة

### 🔒 حماية المقاطع من التحميل
- **إخفاء المصدر**: رابط ملف الفيديو المباشر لا يُرسل أبدًا إلى متصفح الطالب (null في كل ردود API غير الإدارية)، والمقاطع المرفوعة تُحفظ خارج `public/` ولا تُخدم كملفات ثابتة أبدًا
- **بث موقّع مؤقت**: `/api/clips/:id/stream` يبث الملف (المرفوع من القرص أو الخارجي) عبر الخادم بتوكن HMAC-SHA256 مرتبط بالمستخدم والمقطع، صلاحيته 30 دقيقة، ويدعم Range الكامل (206/416) للتقديم/التأخير، مع `no-store` و`inline`
- **مشغل محصّن**: `controlsList=nodownload`، تعطيل PiP و remote playback، منع قائمة الزر الأيمن والسحب
- **علامة مائية** باسم الطالب المشاهد في 6 مواضع فوق المشغل (رادع لتسجيل الشاشة)
- **بوابة عضوية**: المشاهدة للمسجلين فقط — رابط المقطع المنسوخ يفتح لأعضاء المنصة، والزائر يرى بوابة تسجيل دخول

### ✉️ تأكيد البريد + منع البريد الوهمي
- **التسجيل ببريد حقيقي فقط**: رفض نطاقات البريد المؤقت/الوهمي المعروفة (mailinator وغيرها — قائمة +60 نطاقًا) + فحص سجلات MX للنطاق (النطاق غير موجود أو لا يستقبل رسائل → مرفوض)
- **رمز تأكيد 6 أرقام**: يُرسل بالبريد عند التسجيل، صالح 10 دقائق، يُخزّن كبصمة SHA-256 فقط، حد أقصى 5 محاولات خاطئة، تبريد إعادة إرسال 60 ثانية
- **صفحة /verify** لكل طالب غير موثّق: إدخال الرمز، إعادة إرسال بعددّاد، إرشادات بريد غير مرغوب، وخيار الخروج إن كان البريد خاطئًا
- **بوابة محتوى**: طالب غير موثّق لا يستطيع تسجيل إجابات، بدء/تسليم اختبارات، أو استخدام المساعد الذكي (403) — الدخول يحوّله تلقائيًا لـ /verify، ولافتة تنبيه بلوحته
- **توثيق يدوي من المالك**: شارة «موثّق / غير موثّق» في تتبع الحسابات + زر توثيق فوري — يصلح للوضع اليدوي بدون مزود بريد
- **إرسال حقيقي اختياري**: أضف `RESEND_API_KEY` أو بيانات SMTP (Gmail App Password مثلاً) في `.env` فيصبح الإرسال آليًا بدون أي تعديل بالكود (انظر متغيرات البيئة)
- الحسابات السابقة لنظام التوثيق عُوملت كموثقة عبر سكربت لمرة واحدة `scripts/verify-existing-users.ts`

### 🤖 المساعد الذكي
- مدرّب متخصص في قدرات مبني على `z-ai-web-dev-sdk`
- شرح الحلول خطوة بخطوة، استراتيجيات السرعة، فهم الأخطاء
- زر «اشرح لي بالذكاء الاصطناعي» داخل كل سؤال (يحلل إجابة الطالب الخاطئة تحديدًا)

### 👨‍🏫 لوحة المعلم (6 تبويبات)
نظرة عامة (إحصائيات المنصة + دقة المواضيع + أبرز الطلاب) · إدارة الأسئلة · استيراد الملفات · الطلاب · الاختبارات · الإشراف

### لماذا SQLite بدل PostgreSQL؟
بيئة التشغيل الحالية توفر SQLite. مخطط Prisma **محصّن ومحايد** — الترحيل إلى PostgreSQL أو Supabase يتطلب 3 تعديلات فقط:

```prisma
// prisma/schema.prisma
datasource db {
  provider = "postgresql"          // 1) غيّر المزود
  url      = env("DATABASE_URL")   // 2) ثم في .env:
}
// DATABASE_URL="postgresql://user:pass@host:5432/qudratak?schema=public"
```
```bash
bun run db:push   # 3) أعد الدفع — كل الاستعلامات تعمل دون تغيير
```

## 🚀 التشغيل محليًا

```bash
# 1) تثبيت الحزم
bun install

# 2) متغيرات البيئة
cp .env.example .env
#   عدّل DATABASE_URL و JWT_SECRET حسب حاجتك

# 3) إنشاء قاعدة البيانات
bun run db:push

# 4) توليد بنك الأسئلة (اختياري — يوجد ملف جاهز)
bun run scripts/gen/main.ts

# 5) زرع البيانات الأولية (مستخدمين + أسئلة + اختبارات + نشاط تجريبي)
bun run scripts/seed.ts
bun run scripts/seed-owner.ts   # حساب المالك العام + الأحداث + توزيع النشاط الزمني
bun scripts/seed-rayd.ts        # حساب رائد الحربي (المالك) — owner@example.com
bun scripts/seed-clips.ts       # مقاطع تعليمية تجريبية (6 دروس يوتيوب حقيقية)

# 6) التشغيل
bun run dev        # http://localhost:3000
```

### 🔑 الحسابات التجريبية

| الدور | البريد | كلمة المرور |
|---|---|---|
| 👑 **مالك المنصة (رائد الحربي)** | `owner@example.com` | `OWNER_PASS_PLACEHOLDER` |
| مالك عام (احتياطي) | `owner@qudratak.sa` | `Owner@1234` |
| طالب (بنشاط كامل) | `student@qudratak.sa` | `Student@1234` |
| طالب ضعيف الأداء | `reem@qudratak.sa` | `Student@1234` |
| معلم | `teacher@qudratak.sa` | `Teacher@1234` |
| معلم ثانٍ | `sara@qudratak.sa` | `Teacher@1234` |

> **استعادة كلمة المرور**: من صفحة الدخول زر «نسيت كلمة المرور؟» — الطلاب يتواصلون
> مع المالك ليُعيّن كلمة جديدة لهم من لوحة «تتبع الحسابات» (زر المفتاح 🔑)،
> والمالك نفسه يستخدم سكربت الطوارئ:
> `bun run scripts/reset-password.ts <البريد> <الكلمة الجديدة>`
> وكل مستخدم مسجّل الدخول يغيّر كلمته بنفسه من «الملف الشخصي». كلمات المرور مشفّرة bcrypt.

> **التسجيل من الصفحة العامة للطلاب فقط** — كل حساب جديد يُحفظ فورًا في قاعدة البيانات
> بدور «طالب» بغض النظر عن أي بيانات مُرسلة (حتى محاولات حقن الدور تُرفض تلقائيًا).
> حسابات المعلمين ومالك المنصة تُنشأ بزرع السكربتات أعلاه أو من لوحة المالك (تغيير الدور).

> **جلسة تعمل في كل البيئات**: عند الدخول/التسجيل يُرجع الخادم توكن JWT يُحفظ في
> localStorage ويُرفق تلقائيًا (Authorization: Bearer) مع كل استدعاءات /api، فلا يسقط
> الدخول داخل iframes المعاينة أو أي بيئة تحجب الكوكيز — مع كوكي SameSite=None;
> Secure; Partitioned (CHIPS) عبر HTTPS. عند تسجيل الخروج يُمسح التوكن والكوكي معًا.
>
> **لوحة المالك** (تظهر فقط لحساب المالك) تشمل: تتبع جميع الحسابات مع إحصائيات كل طالب
> (عدد الأسئلة الصحيحة، الدقة، متوسط الاختبارات، آخر نشاط)، تغيير الأدوار (طالب ↔ معلم)،
> حظر/تعليق الحسابات، حذف الحسابات، إنشاء وإدارة الأحداث والمسابقات، إدارة **المقاطع التعليمية**،
> واستيراد الأسئلة، وإضافة أسئلة يدويًا في **جميع الأقسام** (الكمي بمواضيعه العشرة واللفظي بمواضيعه الستة).

## 🛡️ الحماية من الهجمات السيبرانية وضغط السيرفر (Task 12)

درع متعدد الطبقات يحمي المنصة من التخمين والإغراق والطلبات الآلية:

| الطبقة | الحماية | التفاصيل |
|--------|---------|----------|
| **Middleware عام** (`src/proxy.ts`) | ترويسات أمان على كل الردود | CSP (منع Clickjacking عبر `frame-ancestors` + حظر `object-src` + تقييد مصادر الإطارات ليوتيوب/Vimeo)، nosniff، Referrer-Policy، Permissions-Policy (قطع الكاميرا/الميكروفون)، HSTS |
| | حد عام للطوفان | **240 طلب/دقيقة لكل IP** على كل الـ APIs (يستثني بث الفيديو لأن مشغله يطلق طلبات Range متكررة طبيعيًا) → 429 |
| | حجب الأجسام الضخمة | أي طلب API بجسم > 10MB → 413 مبكرًا |
| **قفل الحسابات** (`src/lib/rate-limit.ts`) | ضد تخمين كلمات المرور | **5 محاولات خاطئة → قفل 15 دقيقة** على الحساب (423) بغض النظر عن الجهاز، مع تنبيه الطالب بعدد المحاولات المتبقية |
| **حدود دقيقة لكل مسار** | | |
| `POST /api/auth/login` | 10/دقيقة لكل IP | + القفل أعلاه |
| `POST /api/auth/register` | 10/ساعة لكل IP | يمنع التسجيل الجماعي الآلي (مع فحص MX والنطاقات المؤقتة من Task 11) |
| `POST /api/auth/verify` | 12/دقيقة لكل IP | + حد 5 محاولات لكل رمز (Task 11) |
| `POST /api/auth/resend` | 6/10 دقائق لكل IP | + تبريد 60 ثانية لكل مستخدم — يمنع الإزعاج البريدي |
| `PUT /api/auth/password` | 5/10 دقائق لكل مستخدم | |
| `POST /api/ai/*` | 20/دقيقة لكل مستخدم + 30/دقيقة لكل IP | حماية تكلفة استدعاءات الذكاء الاصطناعي |
| بدء/تسليم الاختبارات | 30/دقيقة لكل مستخدم | يمنع إغراق المحاولات |
| استيراد الأسئلة | 5 ملفات/10 دقائق | عملية ثقيلة على القاعدة |
| إضافة تعليقات | 20/دقيقة لكل مستخدم | يمنع السبام |

**ملاحظات تقنية:**
- العدّادات في الذاكرة (نافذة ثابتة + تنظيف دوري بسقف 50 ألف مفتاح — لا تتحول الحماية نفسها إلى ثغرة ذاكرة). مناسبة لخادم واحد؛ للتوسع الأفقي مستقبلًا تُستبدل بـ Redis بنفس الواجهة.
- IP العميل يُقرأ من **آخر** عنصر في `X-Forwarded-For` (الذي يضيفه البروكسي الموثوق) — انتحال الترويسة لا يتجاوز الحدود.
- استجابة 429 تتضمن `Retry-After` ورسالة عربية واضحة.

**حدود صادقة (طبيعة الويب):** حماية التطبيق توقف التخمين والإغراق عالي المستوى والسبام — أما هجوم DDoS حجومي يشبع عرض النطاق نفسه فيُصدّ على مستوى البنية التحتية عند النشر: ضع المنصة خلف Cloudflare (مجاني) أو WAF المزوّد، وستضاف طبقة الصواريخ المضادة فوق هذا الدرع.

### 📮 الحائط الرباعي ضد البريد الوهمي/العشوائي (Task 11 + 13)

عند التسجيل يمر البريد بأربعة فحوص متتابعة قبل قبوله:

1. **النطاقات المؤقتة** (70+ نطاق معروف: mailinator/temp-mail/yopmail…) → رفض فوري
2. **الأنماط العشوائية الواضحة** — حرف مكرر 5 مرات (`aaaaa123`) أو 12+ حرفًا بلا حروف علة (`xkqwrtyplkjm`) → رفض (قواعد آمنة: أرقام الجوالات وأسماء الطلاب الطبيعية لا تُمس)
3. **سجل MX** — نطاق لا يستقبل بريدًا أصلًا → رفض
4. **SMTP Mailbox Probe** (`src/lib/mailbox-probe.ts`) — الأقوى: نتواصل بخادم بريد النطاق ونسأله عن الصندوق نفسه؛ إن رد `550 user unknown` (مثل `asdf999@gmail.com` العشوائي) → رفض «هذا البريد غير موجود فعليًا»

> **ملاحظة تشغيلية**: الفحص الرابع يحتاج منفذ 25 صادرًا (متاح في VPS/خوادم حقيقية، محجوب في معظم PaaS). عند الحجوب يتجاوز نفسه تلقائيًا (fail-open + قاطع دائرة 10 دقائق) وتبقى الحماية النهائية هي **رمز التأكيد الإلزامي** — ولتفعيله آليًا 100% أضف `RESEND_API_KEY` أو إعدادات SMTP في `.env` فيصبح رمز التأكيد يصل لصندوق الطالب ولا يفتح المحتوى إلا صاحب البريد الحقيقي.

**اختبارات**: `bun scripts/mailbox-guard-unit.ts` (24 فحص وحدة) + `python3 scripts/test-mailbox-guard-live.py` (5 فحوص حية عبر API).

**اختبارات الحماية:** `python3 scripts/test-security.py` (23 فحصًا — قفل الحساب، حدود المصدر والمستخدم، الطوفان، الأجسام الضخمة، الترويسات). استخدم `--lite` لإعادة التشغيل خلال ساعة من تشغيل سابق (حد التسجيل 10/ساعة). الحدود بالذاكرة: إعادة تشغيل خادم التطوير تصفّرها.

## 🚢 النشر للإنتاج

> **ملاحظة عن الروابط:** المنصة تستخدم مسارات نظيفة بدون `#` (مثل `/dashboard` و`/leaderboard` و`/q/{id}`) عبر History API، مع rewrite في next.config يقدّم التطبيق لأي مسار غير معروف — فتحديث الصفحة أو مشاركة رابط مباشر يعملان دائمًا. الروابط القديمة بنمط `#/path` تُحوَّل تلقائيًا إلى المسار النظيف عند فتحها.

### الخيار الأول: VPS (موصى به)
```bash
# 1) بناء المشروع
bun install && bun run db:push && bun run build

# 2) تشغيل مع pm2
bun add -g pm2
pm2 start "bun run start" --name qudratak

# 3) Nginx كوكيل عكسي + شهادة SSL (certbot)
server {
  server_name qudratak.sa;
  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
```
> عند النشر خلف HTTPS: اجعل `secure: true` في كوكي الجلسة (`src/lib/auth.ts`) وغيّر `JWT_SECRET`.

### الخيار الثاني: Vercel + Supabase
1. أنشئ مشروع Supabase وخذ `DATABASE_URL` (Connection Pooling).
2. ارفع المستودع إلى GitHub ثم استورده في Vercel.
3. أضف متغيرات `DATABASE_URL` و `JWT_SECRET` في إعدادات المشروع.
4. شغّل `bunx prisma db push` محليًا تجاه Supabase ثم `bun run scripts/seed.ts` مرة واحدة.
5. فعّل `secure cookies` كما أعلاه.
